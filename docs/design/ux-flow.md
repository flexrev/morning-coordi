## 1. 정보구조 (IA)

### 1-1. 화면 목록

| id | 화면 | 목적 | 진입 | 비고 |

| S3 | 결과 (재방문 홈) | 클래식 조합 3장 즉시 보기 | 앱 실행(재방문) · S2 · 최근 선택 | 홈 = 마지막 선택의 결과 |
| S4 | 더 보기 | 톤별 / 색상별 / 변주 섹션 탭 | S3 "더 보기" | 가로 탭 바, 아코디언 아님 |
| S5 | 조합 상세 | 카드 한 장 크게 + 핏·소재·신발·기장 칩 | S3·S4 카드 탭 | 칩 탭 → S6 |
| S6 | 상세 시트 (바텀시트) | 핏 밸런스·소재 계절·신발 스타일·기장 설명 | S5 칩 탭 | 화면 전환 아님, 반쯤 올라오는 시트 |
| O1 | 설치 안내 (오버레이) | iOS 3단계 그림 / Android 설치 버튼 | 2회차 방문 이후 S3 상단 카드 → 시트 | 모달 자동 노출 금지 |
| E1 | 엣지 상태 | 결과 없음 · 오프라인 미캐시 · 저장 데이터 소실 | 조건 발생 시 S3 자리 | 5장 |

화면 6개 + 오버레이 1 + 엣지 상태. 설정 화면 없음(계절 토글이 유일한 설정이며 S3 상단에 있음).

### 1-2. 화면 맵

```
[앱 실행]
   │
   ├─ 저장된 마지막 선택 없음 ──▶ S1 카테고리 ──탭①──▶ S2 색 칩 ──탭②──▶ S3 결과
   │                                ▲                      ▲                 │
   └─ 저장된 마지막 선택 있음 ──────┼──────────────────────┼────────────▶ S3 결과 (홈)
                                    │                      │                 │
                       하단 카테고리 줄 (S3)      기준 아이템 바 "색 바꾸기" (S3)   │
                                                                              │
                     ┌────────────────────────────────────────────────────────┤
                     │                                                        │
                [최근 선택 3] ──탭①──▶ S3 (다른 기준 아이템의 결과)        [계절 토글] (제자리 갱신)
                     │
                     │   S3 ──"더 보기"──▶ S4 ─┬─ 톤별 (기본) ─ 톤 그룹 칩 ─ 카드
                     │                          ├─ 색상별 ─ 유사·보색·무채색 칩 ─ 카드
                     │                          └─ 변주 ─ 카드(바꾼 아이템 표시)
                     │                                │
                     │   S3 카드 ─────────────────────┴─▶ S5 조합 상세 ──칩 탭──▶ S6 상세 시트
                     │
                     └── O1 설치 안내: S3 상단 카드 → 시트 (iOS 그림 / Android 버튼)
```

내비게이션 규칙
- 뒤로 가기: 모든 화면은 상단 왼쪽 "‹" 와 시스템 뒤로(히스토리) 모두 지원. 설치형(standalone)에서는 브라우저 뒤로가 없으므로 `history.pushState` 로 S2·S4·S5·S6 를 각각 히스토리 항목으로 둔다.
- 하단 탭 바 없음. 화면이 6개뿐이라 전역 탭 바는 오히려 엄지 영역을 낭비한다. 하단은 항상 "지금 화면의 1차 동작"만.

## 2. Quick 경로 (홈 → 결과 2탭 고정)

### 2-1. 단계

| 단계 | 화면 | 사용자 동작 | 화면이 보여주는 것 | 다음에 뭐가 나올지 알려주는 장치 |
|---|---|---|---|---|
| 0 | 실행 | 홈 아이콘 탭 | 첫 실행: S1 / 재방문: S3 | 스플래시 1초 이내 |
| ① | S1 | 카테고리 버튼 1개 탭 | 하단 2×2: **하의 · 상의 · 신발 · 아우터** | 버튼 밑에 "색을 고르면 바로 조합이 나와요" 보조문 |
| ② | S2 | 색 칩 1개 탭 | 해당 카테고리 색 칩 그리드(3열, 최대 12칩), 칩 밑에 색 이름 | 상단 제목 "하의 색은?" + 칩마다 이름 |
| 결과 | S3 | 없음 | 클래식 3장이 스크롤 없이 보임 | 카드에 "클래식 1/3 · 2/3 · 3/3" 라벨 |

탭 수: **2**. 탭 ①과 ② 사이에 확인 버튼·전환 애니메이션 대기 없음. 칩 탭 즉시 S3 렌더(데이터는 전부 로컬 JSON이므로 100ms 이내 목표).

### 2-2. 첫 실행 흐름

```
스플래시 → S1 (인사 한 줄 "오늘 입을 옷, 하나만 고르세요") → ① 카테고리 → ② 색 칩 → S3
```
- 온보딩 캐러셀·권한 요청·설치 배너 **없음**. 첫 실행은 결과를 보는 것으로 끝난다.
- S1 의 "최근 선택" 영역은 비어 있으면 아예 그리지 않는다(빈 상태 문구 없음).
- 선택이 끝나면 `lastSelection` 과 `recents[0]` 에 저장.

### 2-3. 재방문 흐름

```
스플래시 → S3 (마지막 선택의 결과가 바로 보임, 탭 0)
```
- 상단 기준 아이템 바: "하의 · 인디고 데님" + 색 칩. 탭하면 S2(같은 카테고리의 색 그리드)로 → 색만 바꾸기 2탭.
- 최근 선택 3개: 기준 아이템 바 아래 가로 칩 3개(현재 것 강조). 다른 것을 탭하면 S3 즉시 갱신 → **1탭**.
- 하단 고정 영역: "더 보기" 버튼 + 카테고리 4개 줄(하의·상의·신발·아우터). 카테고리 탭 → S2 → 칩 → S3. 즉 재방문에서도 **기준 아이템 변경 = 2탭**. S1 을 거치지 않는다.
- `lastSelection` 이 없거나(iOS 7일 저장소 삭제) 깨져 있으면 조용히 S1 로 간다. 오류 문구 없음.

### 2-4. 계절 토글

- 위치: S3 상단, 제목 줄 바로 아래 세그먼트 3개 **봄가을 | 여름 | 겨울**. 저빈도 조작이므로 상단(엄지 밖) 허용.
- 기본값: 현재 월로 자동(3~5·10~11 봄가을, 6~9 여름, 12~2 겨울). 사용자가 바꾸면 `season` 에 저장하고 이후엔 저장값 우선. 월이 바뀌어 자동값과 저장값이 다르면 토글 옆에 작은 점 하나로만 표시(강제 변경 없음).
- 동작: 탭 1번에 S3 제자리 갱신. 화면 전환 없음, 스크롤 위치 유지.

## 3. Deep 경로 (≤ 6탭)

점진적 공개는 **2단계만**: 결과(클래식 3) → "더 보기" 탭 바 → 카드 안 칩. 그 아래 단계는 없다.

### 3-1. 더 보기 (S4)

- 진입: S3 하단 "더 보기" (1탭). 상단에 기준 아이템 바 유지(지금 뭘 기준으로 보는지 항상 보임).
- 가로 탭 바 3개: **톤별 | 색상별 | 변주**. 기본 선택 = 톤별. 탭 바는 상단 고정(sticky)이되 스크롤 시 숨기지 않음.
- 톤별: 탭 바 아래 톤 그룹 칩 줄 — **뉴트럴 · 어스톤 · 모노톤 · 네이비 베이스 · 포인트 컬러** (가로 스크롤, 48px). 기본 = 기준 아이템이 속한 톤 그룹(인디고 데님이면 네이비 베이스). 칩 탭 → 그 톤 그룹 안의 조합 카드 목록.
- 색상별: 칩 줄 — **유사색 · 보색 · 무채색**. 기본 = 유사색. 칩 탭 → 해당 색상환 관계의 조합 카드.
- 변주: 칩 줄 없음. 클래식 1~3 각각에서 아이템 하나만 바꾼 변주 3~5장. 카드마다 "클래식 N에서 ○○만 바꿈" 한 줄.
- 카드는 S3 와 같은 카드 컴포넌트(아래 4장). 탭하면 S5.

### 3-2. 조합 상세 (S5) 와 상세 시트 (S6)

- S5: 일러스트 크게(화면 폭의 60%) + 색 칩 3~4개 + 캡션. 그 아래 **상세 칩 4줄** — 각 줄은 "항목 이름 → 값" 형태의 칩이고 탭하면 S6.
  - **핏** → "레귤러 상의 + 스트레이트 하의"
  - **소재** → "저지 · 인디고 데님 · 가죽"
  - **신발 스타일** → "흰 스니커즈"
  - **기장** → "레귤러 상의 · 노브레이크"
- S6 (바텀시트, 화면 높이 50~60%): 칩의 항목 하나에 대한 설명.
  - 신발 스타일: 이 조합에 맞는 신발 종류 목록(흰 스니커즈·페니 로퍼·척카 부츠 …)과 한 줄 메모(예: "가죽형이면 슬랙스 OK"). 점수 숫자는 노출하지 않고 "클래식 / 변주" 라벨만.
  - 핏: 상·하 핏 밸런스 한 줄 + 대안 핏 1~2개.
  - 소재: 계절 적합 표시(봄가을·여름·겨울 중 가능한 것만 진하게) + 어울리는 소재 2~3개.
  - 기장: 용어 도움말(노브레이크 = "밑단이 신발에 닿을락 말락") + 신발과의 궁합 한 줄.
  - 시트 안의 대안(예: 다른 신발)을 탭하면 **S5 가 그 아이템으로 바뀐 변주**로 갱신되고 시트는 닫힌다. 새 화면을 열지 않는다.
- 시트 밖 탭·아래로 끌기·뒤로 가기로 닫힘.

### 3-3. "피하기" 경고가 드러나는 방식

Quick 경로는 클래식(score 5·4)만 보여주므로 경고가 **나올 일이 없다**. 경고는 Deep 경로에서만, 다음 세 자리에 나온다.

| 자리 | 형태 | 예 |
|---|---|---|
| S4 각 탭의 맨 아래 | 접힌 줄 "이 아이템과 피할 것 N개 ▸" — 탭하면 그 자리에서 펼침 | 인디고 데님: "같은 워시의 데님 재킷 — 유니폼처럼 보임", "4색 이상" |
| S5·S4 카드 모서리 | **의견 갈림(disputed)** 작은 표식 "⚑". 카드 자체는 그대로 노출. 탭하면 S6 에 한 줄 이유 | "블랙 구두 + 진청: 출처에 따라 갈림. 진청엔 가능, 연청엔 비추" |
| S6 안 대안 목록 | 조건부(score 3)는 "변주" 라벨 + 조건 한 줄, 비추(2) 는 흐리게 + "비추" 라벨, 차단(1) 은 목록에서 제외 | 차콜 바지 → 탄 구두: 제외 |

규칙: 경고는 **차단하지 않는다**(선택을 막는 UI 없음). 흐리게·라벨·한 줄 이유까지만. 모달 경고 없음.

## 4. 결과 화면 해부 (S3)

위에서 아래로:

1. **상단 바** (safe-area 포함, 저빈도 영역): 앱 이름 작게 · 계절 토글 세그먼트.
2. **기준 아이템 바** (56px): 카테고리 라벨 + 색 칩 + 색 이름 ("하의 · 인디고 데님") + 오른쪽 "색 바꾸기 ›". 탭 → S2.
3. **최근 선택 줄** (48px): 칩 3개 가로. 현재 것 강조. 2개 이하면 있는 만큼만. 0개면 줄 자체 생략.
4. **클래식 카드 ×3** (고정): 스크롤 없이 세 장이 한 화면에 들어와야 하므로 **가로형 컴팩트 카드**(높이 ≈ 128px).
5. **하단 고정 영역** (엄지 영역): "더 보기" 56px 버튼 + 카테고리 4개 줄(각 48px).

### 4-1. 카드 한 장이 보여주는 것

| 요소 | 내용 | 규칙 |
|---|---|---|
| 라벨 | "클래식 1/3" (S4 에선 "뉴트럴" / "변주 · 클래식 1에서 신발만") | 왼쪽 위, 작은 글자 |
| 일러스트 | 단일 토르소 실루엣에 색 주입 (D2·C3) | 카드 왼쪽, 96×120 |
| 색 칩 3~4개 | 순서 고정: **상의 · 하의 · 신발 · (아우터)**. 아우터는 계절이 여름이면 생략 | 24px 원형, 다크 배경에서 1px 밝은 테두리 |
| 캡션 한 줄 | 아이템마다 **색 · 소재 · 품목** 어순, "·" 로 연결 | 예: "화이트 저지 티 · 인디고 데님 · 화이트 가죽 스니커즈". 2줄까지 허용, 말줄임 금지 |
| 표식 | disputed 면 "⚑" | 카드 오른쪽 위, 클래식 3장엔 원칙적으로 없음 |

색 칩 3~4개는 **기준 아이템을 포함**한다(기준 아이템 칩은 테두리를 두 겹으로 해 "이건 당신이 고른 것"을 표시).

### 4-2. 카드를 탭하면

S5 조합 상세로 간다(일러스트 확대 + 상세 칩 4줄). 카드 안에 별도의 작은 버튼(즐겨찾기·공유 등)은 두지 않는다 — MVP 범위 밖이고 오탭을 만든다.

### 4-3. 변주 카드의 모양

- 원본 클래식과 같은 카드 모양에서 **바뀐 아이템 칩 하나만 점선 테두리 + "바꿈" 꼬리표**.
- 라벨: "변주 · 클래식 1에서 **신발**만".
- 캡션: 바뀐 아이템을 굵게. "화이트 저지 티 · 인디고 데님 · **브라운 첼시 부츠**".
- 변주는 색·소재·신발 스타일 중 하나만 바뀐다(두 개 이상 바뀐 것은 변주가 아니라 다른 조합 → 톤별/색상별에 들어감).

## 5. 엣지 상태

| 상태 | 언제 | 화면 | 문구 (짧게) |
|---|---|---|---|
| 결과 없음 | 계절 필터 후 클래식이 0장 (예: 린넨 상의 기준 + 겨울) | S3 카드 자리에 빈 상태 1장 + "다른 계절 보기" 버튼. 변주가 있으면 그 아래 "변주 N개 보기" | "겨울엔 이 조합이 없어요" |

## 6. PWA 설치 안내 (O1)

### 6-1. 노출 규칙

- 조건: 미설치(`display-mode: standalone` 아님 & `navigator.standalone` 아님) **그리고** 2회차 방문 이상 **그리고** 하루 1회 **그리고** 닫은 지 7일 경과.
- 저장 키: `visitCount`, `installBannerShownAt`, `installBannerDismissedAt` (localStorage, 잃어도 됨).
- 자리: S3 의 기준 아이템 바 **위** 에 끼워 넣는 카드 1장(모달 아님, 하단 엄지 영역 침범 금지). 결과 카드가 먼저 렌더된 뒤 나타남.
- 문구: "홈 화면에 두면 아침에 1초 만에 열려요" + [설치 방법] + [닫기 ✕].

### 6-2. iOS Safari

- `beforeinstallprompt` 가 없으므로 [설치 방법] → 바텀시트에 **3단계 그림**:
  1. 하단 **공유** 버튼(네모에 화살표 아이콘)
  2. 아래로 내려 **"홈 화면에 추가"**
  3. 오른쪽 위 **"추가"**
- 그림은 D2 가 아이콘으로 제작. 글은 각 단계 한 줄.
- 완료 감지가 불가능하므로 시트에 "다 했어요" 버튼 → 배너 영구 숨김(`installBannerDismissedAt = forever`).

### 6-3. Android Chrome

- `beforeinstallprompt` 를 저장해 두고 배너의 버튼을 **[설치]** 로 바꿈. 탭 → `prompt()`.
- `appinstalled` 수신 시 배너 제거. 사용자가 거절하면 7일 숨김.
- manifest `screenshots[narrow]` 1장 이상 넣어 Richer Install UI 사용(C1).

### 6-4. 그 외 브라우저 / 데스크톱

- 배너 비노출. MVP 는 모바일만 안내한다.

## 9. D2 / C1 에게 묻는 것 (최대 8)

1. **(C1·C2) 신발·아우터 기준 데이터.** R1 페어링은 하의 12·상의 10 베이스만 있다. S1 의 "신발·아우터" 버튼을 켜려면 역방향 조회(하의·상의 표에서 신발/아우터 열을 뒤집기)로 결과를 만들 수 있는가? 안 되면 MVP 1차에서 두 버튼을 "곧 추가" 비활성으로 둘지 결정 필요.
2. **(C1·C2) 클래식 3장 선정 규칙.** score 5 → universal → 톤 그룹이 서로 다른 것 순으로 3장을 뽑는 것을 제안한다. 세 장이 모두 "흰 스니커즈"로 끝나지 않도록 신발 색 다양성 조건을 넣을지?
3. **(C1) 계절 기본값.** 현재 월로 자동 설정 후 사용자 변경값 우선(2-4절). 수용 가능한가? localStorage 키는 `lastSelection`, `recents[3]`, `season`, `visitCount`, `installBannerShownAt`, `installBannerDismissedAt` 6개로 제안.
4. **(C1) 히스토리 처리.** standalone 에서 S2·S4·S5·S6 를 `pushState` 항목으로 두고 시트(S6)도 뒤로 가기로 닫히게 하는 방식 — 라우터 없이 가능한가?
5. **(D2) 컴팩트 카드.** 96×120 실루엣이 35 path 이내 플랫 SVG 로 상·하·신발·아우터를 구분해 보이는가? 안 보이면 카드를 세로형으로 키우고 클래식 3장 중 3번째는 스크롤 허용으로 바꾼다.
6. **(D2) 색 칩 + 이름.** 56px 칩 아래 14px 이름 2줄("그레이 멜란지", "라이트워시 데님")을 3열 그리드에 넣으면 12칩이 하단 40% 에 들어가지 않는다. 칩 48px + 이름 1줄(줄임 없이 짧은 이름)로 갈지, 그리드를 화면 중앙까지 올릴지.
7. **(D2) disputed 표식.** "⚑" 글리프 대신 아이콘을 만들지, 색은 액센트가 아닌 중립 회색으로 할지. 접근성 라벨은 "의견 갈림"으로 제안.
8. **(D2·팀5) 캡션 길이.** "색 · 소재 · 품목" 어순으로 3~4 아이템을 쓰면 40자를 넘긴다(예: "라이트블루 옥스포드 셔츠 · 베이지 치노 · 브라운 페니 로퍼 · 네이비 블레이저"). 소재가 품목명에 포함된 경우(옥스포드·치노·데님) 중복을 생략하는 규칙을 팀5 라벨에 넣어도 되는가?

# 아침 코디 (가칭 Morning Coordi) — 팀 구성 및 제작 계획

작성일: 2026-10-19
버전: v0.1 (승인 대기)

---

## 1. 프로젝트 한 줄 정의

출근 전 바쁜 아침에 **10초 안에** "오늘 이 바지에 뭘 입지?"에 답을 주고,
원하면 색·톤·핏·소재·신발까지 **세부적으로** 파고들 수 있는 남성 코디 가이드 사이트.
핸드폰 홈화면에 추가해 앱처럼 쓰는 **PWA** 형태.

### 핵심 원칙 (모든 팀이 공유)

| 원칙 | 의미 |
|---|---|
| 빠른 길 우선 (Quick Path) | 아이템 하나 고르면 → 바로 그림 예시 + 추천 조합. 탭 3번 이내, 3초 이내 응답 |
| 깊은 길은 선택 (Deep Path) | 톤별 / 색상별 / 바리에이션 / 핏 / 소재 / 신발 스타일은 "더 보기"로 펼침 |
| 클래식 기준 | 유행보다 검증된 클래식 매칭을 기본값으로. 모험적 조합은 "변주"로 별도 표시 |
| 그림이 먼저 | 글보다 실루엣 일러스트 + 색 칩이 먼저 보이게 |
| 오프라인 동작 | 서버 없이도 열림. 엘리베이터·지하철에서도 작동 |
| 한 손 조작 | 엄지 영역에 주요 버튼. 어두운 아침을 위한 다크 모드 기본 지원 |

## 2. 기능 범위

### 2-1. MVP (1차 출시)

**A. 컬러 매칭 (핵심)**
- 기준 아이템 선택: 상의 / 하의 / 신발 / 아우터 중 하나를 고르고 색 선택
  - 예) 하의 → 인디고 데님 → 어울리는 상의 색(흰색, 그레이 멜란지, 네이비, 베이지, 올리브 …) + 신발 색 + 아우터 색
- 결과 표시
  - 추천 조합 카드 (실루엣 일러스트에 색 입힌 그림 + 색 칩 3~4개)
  - "클래식 조합" 3개 고정 노출 → 기본 흰 티 + 인디고 + 흰 스니커즈 같은 안전한 답
  - 더 보기: **톤별**(뉴트럴 / 어스톤 / 모노톤 / 네이비 베이스 / 포인트 컬러), **색상별**(색상환 기준 유사·보색·무채색), **바리에이션**(같은 조합에서 한 아이템만 바꾼 변주 3~5개)

**B. 스타일 매칭**
- 기장: 크롭 / 레귤러 / 롱 (상의·아우터·바지 각각)
- 핏: 슬림 / 레귤러 / 루즈 / 와이드 — 상·하의 핏 밸런스 규칙 (예: 루즈 상의 + 테이퍼드 하의)
- 소재: 데님(인디고/워시드/블랙), 코듀로이(골덴), 치노, 울/플란넬, 니트, 린넨, 저지, 가죽
  - 소재끼리 어울림/안 어울림 매트릭스 + 계절 적합도
- 신발 스타일: 흰 스니커즈, 러닝화, 로퍼, 더비/옥스포드, 첼시부츠, 워크부츠, 샌들/슬리퍼
  - 바지 소재·기장과 신발 조합 규칙 (예: 와이드 데님 + 묵직한 부츠, 치노 + 로퍼)

**C. 빠른 아침 모드 (Quick)**
- 첫 화면: "오늘 입을 바지" 또는 "오늘 입을 상의" 하나만 고르면 끝
- 최근 선택 기억 (localStorage) → 다음날 1탭 재사용
- 계절 토글 (봄가을 / 여름 / 겨울) 로 추천 범위 자동 필터

**D. PWA 기본**
- 홈화면 추가 (iOS Safari / Android Chrome 모두)
- 오프라인 캐시 (Service Worker)
- 스플래시·아이콘·테마 컬러
- 첫 로딩 1초 이내 목표 (정적 파일만)

### 2-2. 2차 (MVP 안정화 후)
- 내 옷장 등록 (가진 옷 색/소재만 등록 → 추천을 내 옷으로 한정)
- 날씨 연동 (오늘 기온 기준 소재·레이어 제안)
- 상황별 프리셋 (출근 / 주말 / 데이트 / 운동)
- 즐겨찾기 조합 저장

### 2-3. 3차 이후
- 여성 버전
- 실제 사진 예시 (라이선스 확인 필요)
- 공유 기능 (조합 카드 이미지 내보내기)

## 4. 단계별 계획과 게이트

```
Phase 0  계획 승인 (지금)
   │
Phase 1  리서치 ───────────── R1 ∥ R2 ∥ R3  (병렬)
   │  게이트: 규칙 표가 JSON으로 옮길 수 있을 만큼 구체적인가?
Phase 2  설계 ────────────── D1 ∥ D2 ∥ C1(스택·스키마)  (병렬)
   │  게이트: 와이어프레임 Quick 경로가 3탭 이내인가? 데이터 스키마 확정
Phase 3  MVP 구현 ─────────── C2 → C3 → C1(통합·PWA)
   │  게이트: 핸드폰에서 홈화면 추가 후 오프라인으로 열리는가?
Phase 4  검토·수정 루프 ───── P1 ∥ P2 ∥ P3 → 수정 → 재검토
   │  게이트: 아침 시나리오 10초 이내 통과, Lighthouse PWA 통과
Phase 5  배포 ──────────────── 정적 호스팅 + 실기기 테스트
```

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 1 리서치 | 규칙 문서 3종 + 원시 데이터 표 | 색 조합 ≥ 60개, 소재 매트릭스 완성, 신발 규칙 ≥ 7종 |
| 2 설계 | IA, 와이어프레임, 토큰, 스키마 | Quick 경로 ≤ 3탭, Deep 경로 ≤ 6탭 |
| 3 구현 | 동작하는 PWA | 데이터 기반 추천 + 일러스트 + 오프라인 |
| 4 검토 | 검토 리포트 3종 + 수정 완료 | 지적사항 심각도 '높음' 0건 |
| 5 배포 | 공개 URL + 홈화면 추가 안내 | 실기기(iOS/Android)에서 홈화면 실행 확인 |

## 5. 기술 방향 (C1이 Phase 2에서 확정, 여기선 기본안)

- **정적 PWA, 서버 없음** — 데이터는 JSON, 로직은 브라우저에서. 호스팅 비용 0.
- 스택 기본안: Vite + 바닐라 JS(또는 Preact) + CSS 변수. 프레임워크 무게 최소화.
- 일러스트: 손그림 이미지 대신 **SVG 실루엣 + CSS 변수로 색 주입** → 모든 색 조합을 그림으로 자동 생성, 용량 ↓
- 소재 표현: SVG 패턴(데님 트윌, 코듀로이 골, 니트 짜임)을 오버레이
- 추천 엔진: 규칙 기반 점수화 (색 호환 점수 + 톤 일치 + 소재 계절 적합 + 핏 밸런스) → 상위 N개
- 저장: localStorage (최근 선택, 즐겨찾기). 2차의 옷장도 로컬 우선.
- 배포: GitHub Pages 또는 Cloudflare Pages (HTTPS 필수 — PWA 조건)

### 데이터 스키마 초안

```
item      { id, category(top|bottom|shoes|outer), name, color, tone, material, fit, length, seasons[] }
colorRule { base, matches[{color, score, tag(classic|variation)}], avoid[] }
matRule   { material, pairsWith[], avoid[], seasons[] }
fitRule   { topFit, bottomFit, score, note }
shoeRule  { shoe, bottoms[{material, fit, length, score}] }
outfit    { id, items[], tags[], isClassic }   // 예시 조합 (리서치에서 수집)
```

## 6. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 기능이 자꾸 늘어남 | MVP 범위(2-1) 밖은 전부 2차로. PM이 게이트마다 재확인 |
| 그림 자산 만드는 비용 | 실루엣 SVG 몇 종 + 색 주입으로 해결. 사진은 3차 |
| 패션 조언의 주관성 | "클래식"은 리서치에서 출처 2개 이상 겹치는 조합만 채택. 나머지는 '변주' 태그 |
| iOS PWA 제약 | 푸시 없음, 저장공간 제한 → MVP는 조회 중심으로 설계하므로 영향 적음 |
| 아침에 안 열어보게 됨 | Quick 경로를 첫 화면에, 최근 선택 1탭 재사용으로 습관화 |

## 7. 확인 필요한 결정 (사용자)

1. **앱 이름** — 가칭 "아침 코디". 다른 이름 원하면 지정
2. **배포처** — GitHub Pages(무료, 간단) vs Cloudflare Pages vs Vercel
3. **일러스트 스타일** — 단색 실루엣(빠름·깔끔) vs 선이 있는 플랫 일러스트(정보량 ↑, 제작 ↑)
4. **MVP에 '내 옷장' 포함 여부** — 기본안은 2차로 미룸
5. **UI 언어** — 한국어 기본, 영어 병기 여부

## 9. 변경 이력

### v0.2 (2026-10-19) — Phase 1 게이트 통과 후 수정

상세는 `research/gate-1-review.md`. 요약:

- **스키마 추가** (5절 보강): `lengthRule`(상의·아우터·바지 기장 × 하의 핏), `outerRule`(계절별 아우터 × 하의·신발), `formality`(카테고리별 포멀도 레벨, 격차 ≥5 차단·4 경고), `adjust[]`(조건부 가감점), `layerRule`(계절별 최대 레이어·순서), `toneRule`(톤 그룹 간 가감점). ID 표기는 camelCase로 통일
- **일러스트 확정**: 플랫 SVG 단일 토르소 + CSS 변수 색 주입, 단색 fill, 소재는 pattern 오버레이, path 35개 이내 → 미결정 3번 해소
- **Quick 경로**: 2탭(카테고리 → 색 칩) 고정, 홈 = 마지막 선택의 결과 화면
- **Phase 4 게이트 교체**: "Lighthouse PWA 통과" → "DevTools Application 패널 체크 + 실기기 오프라인 실행" (Lighthouse PWA 카테고리 삭제됨)
- **iOS 대응** 추가: apple-touch-icon 180px, viewport-fit=cover + safe-area 폴백, 설치 안내 배너
- **MVP 제외 확정**: 체형 보정, 퍼스널컬러, 배기/벌룬 핏 → 2차
- **미결정 유지(비차단)**: 호스팅(GitHub Pages vs Cloudflare Pages)은 Phase 5에서 결정. 앱 이름은 "아침 코디" 가칭 유지
